# מערכת ניהול צוות

מערכת פנימית שמחליפה שלוש עבודות ידניות של מנהלת הצוות: דיווח נוכחות בוקר, מעקב ביצוע יומי מול יעד, וחישוב והעברת בונוס חודשי לשכר.

## מבנה

```
team_manager/
├── server/
│   ├── TeamManager.slnx
│   ├── TeamManager.Api/      ASP.NET Core 10 Web API + EF Core (SQL Server)
│   └── TeamManager.Tests/    בדיקות יחידה (xUnit)
└── client/                   React + TypeScript + Vite + MUI (RTL)
```

## דרישות מקדימות

- .NET 10 SDK
- SQL Server 2022 Express (או כל SQL Server אחר; מחרוזת החיבור ב-`appsettings.json`)
- Node.js 20 ומעלה

## הרצה בפיתוח

```bash
# פעם ראשונה: כלי המיגרציות
dotnet tool restore

# שרת (פורט 5080). בפיתוח מסד הנתונים נוצר ומתעדכן אוטומטית בעלייה.
cd server/TeamManager.Api
dotnet run

# לקוח (פורט 5173), בחלון נוסף
cd client
npm install
npm run dev
```

לפתוח את http://localhost:5173.

משתמשות לפיתוח (מוגדרות ב-`appsettings.Development.json`, נוצרות רק כשטבלת המשתמשות ריקה):

| משתמש | סיסמה | תפקיד |
|---|---|---|
| `teamlead` | `TeamLead!2026` | מנהלת צוות |
| `manager` | `Manager!2026` | מנהלת (צפייה) |

## מסד נתונים

מחרוזת החיבור: `ConnectionStrings:Default` ב-`server/TeamManager.Api/appsettings.json`.
ברירת המחדל היא `localhost\SQLEXPRESS` עם התחברות Windows.

יצירת מיגרציה אחרי שינוי במודל:

```bash
cd server
dotnet ef migrations add <Name> --project TeamManager.Api
```

## מיילים

השליחה נעשית דרך MailKit. הגדרות השליחה בסעיף `Email` ב-`appsettings.json`: `From`, `SmtpHost`, `SmtpPort`, `EnableSsl`, ואם השרת דורש התחברות גם `UserName` ו-`Password` (את הסיסמה להגדיר במשתנה סביבה או בקובץ שלא נכנס ל-Git).

בפיתוח מוגדר `PickupDirectory`, ולכן מיילים לא נשלחים באמת אלא נשמרים כקבצי `.eml` בתיקייה `server/TeamManager.Api/mail-outbox/` (אפשר לפתוח אותם ב-Outlook). כל ניסיון שליחה, מוצלח או לא, נרשם בטבלה `EmailLog`.

- **דיווח נוכחות**: נשלח למייל המנהלת שמוגדר במסך ההגדרות: X מתוך Y נוכחות ורשימת החסרות עם הסיבה. שליחה חוזרת של אותו יום יוצאת כ"עדכון" ומפרטת מה השתנה מאז השליחה הקודמת.
- **תזכורת**: בימים א'-ה', חוץ מימים שהוגדרו כחגים במסך ההגדרות, אם עד שעת התזכורת הדיווח של היום לא נשלח, נשלחת תזכורת אחת למייל של משתמשות מנהלת הצוות.

## עוזר AI

כפתור "עוזר AI" בכל מסך פותח צ'אט ששואלים בו שאלות על הנתונים ("כמה בונוס קיבלה שרה באפריל?"). העוזר משתמש ב-Claude (Anthropic) עם כלים לקריאה בלבד: עובדות, נוכחות, ביצוע יומי, סיכום חודשי, בונוסים ולוח שנה. אין לו אפשרות לשנות נתונים.

- **מפתח API**: נוצר ב-[console.anthropic.com](https://console.anthropic.com) (בתשלום לפי שימוש). בלי מפתח העוזר כבוי ומציג הודעה.
  - בפיתוח (מתוך `server/TeamManager.Api`, המפתח לא נשמר בפרויקט): `dotnet user-secrets set "Assistant:ApiKey" "<המפתח>"`
  - בשרת: `Assistant:ApiKey` בקובץ `appsettings.Production.json`.
- **מודל**: `Assistant:Model` (ברירת מחדל `claude-haiku-5-5`, הזול ביותר, עם מאמץ חשיבה נמוך). אפשר להחליף ל-`claude-sonnet-5-5` או `claude-opus-5-5` אם התשובות לא מספיק טובות, במחיר גבוה יותר.
- **פרטיות**: השאלה והנתונים שהעוזר שולף (שמות, היעדרויות וסיבות, בונוסים) נשלחים ל-Anthropic. לפי האפיון, שימוש ב-AI חיצוני דורש אישור IT.
- **מגבלה**: עד 20 שאלות בדקה לכל משתמשת.

## בנייה לפרודקשן

```bash
cd client
npm run build:server       # בונה את הלקוח לתוך server/TeamManager.Api/wwwroot
cd ../server/TeamManager.Api
dotnet publish -c Release
```

השרת מגיש את הלקוח מאותה כתובת. בפרודקשן יש להגדיר `InitialUsers` (או ליצור משתמשות ידנית) ומחרוזת חיבור, דרך משתני סביבה או `appsettings.Production.json` שלא נכנס ל-Git.

## העלאה לאחסון חיצוני (MonsterASP.NET)

> לפי האפיון המערכת אמורה לרוץ על שרת פנימי. אחסון חיצוני מוציא מידע על היעדרויות ובונוסים מהארגון; זו החלטה של בעלת המערכת.

1. **בפאנל של MonsterASP**: ליצור אתר ומסד MSSQL, ולשמור את מחרוזת החיבור ואת פרטי ההעלאה (Web Deploy או FTP).
2. **סיסמת מייל**: ב-Gmail להפעיל אימות דו-שלבי וליצור "סיסמת אפליקציה".
3. **הגדרות**: להעתיק את `server/TeamManager.Api/appsettings.Production.example.json` ל-`appsettings.Production.json` באותה תיקייה ולמלא. הקובץ לא נכנס ל-Git, אבל עולה לשרת יחד עם האתר.
4. **בנייה**:
   ```bash
   cd client && npm run build:server
   cd ../server/TeamManager.Api && dotnet publish -c Release -o ../../publish
   ```
5. **העלאה**: להעלות את תוכן התיקייה `publish` לאתר (Web Deploy או FTP).
6. **כניסה ראשונה**: המיגרציות רצות והמשתמשות מ-`InitialUsers` נוצרות. להיכנס, להחליף סיסמה ("שינוי סיסמה" בפס העליון), ואז למחוק את `InitialUsers` מהקובץ בשרת.
7. **שמירה על האתר ער**: באחסון חינמי האתר "נרדם" כשאין גלישה, ואז התזכורת והסיכום החודשי לא יוצאים. להגדיר ב-[cron-job.org](https://cron-job.org) (חינמי) בקשה ל-`https://<האתר>/api/health` כל 10 דקות.
8. **בדיקה**: לשלוח דיווח נוכחות ולוודא שהמייל הגיע. אם לא, לבדוק בטבלה `EmailLog` את השגיאה (חלק מהאחסונים החינמיים חוסמים שליחת מיילים).

אבטחה: עד 5 ניסיונות כניסה בדקה לכל כתובת, עוגייה רק ב-HTTPS, ואזור הזמן נקבע ב-`App:TimeZone` (ברירת מחדל ישראל), לא לפי השרת.

## החלטות

- **שליחה לשכר**: רק לחודש שהסתיים, ורק כשלכל עובדת בטבלה יש סכום (גם 0). החודש ננעל רק אם המייל יצא בהצלחה, כדי שלא יישאר חודש נעול שאף אחד לא קיבל. אין ביטול נעילה מהממשק.

- **יום חלקי**: היעד של אותו יום = היעד המלא × אחוז העבודה, מעוגל (לפחות 1). ב-`DailyStatus` נשמרים גם היעד המלא (`BaseTarget`) וגם האחוז, כך ששינוי ברישום בלוח השנה מחשב מחדש את היעד והסטטוס, אבל שינוי יעד של העובדת עדיין לא משנה ימים קודמים.
- **לוח שנה מול נוכחות**: רישום בלוח הוא ברירת מחדל בלבד. נוכחות שכבר נשמרה לא משתנה אוטומטית; במסך הנוכחות מוצג מה שמתוכנן.

- **התחברות בעוגייה (HttpOnly)** במקום JWT: לאפליקציה פנימית שהלקוח והשרת שלה באותה כתובת, עוגייה מאובטחת פשוטה יותר ובטוחה יותר (הטוקן לא נגיש ל-JavaScript). אם החברה תאשר Windows Authentication, אפשר להחליף בלי לגעת בשאר הקוד.
- **סיסמאות** נשמרות כ-hash עם `PasswordHasher` של ASP.NET Core Identity (PBKDF2).
- **ספי סטטוס**: הסטטוס נשמר ברשומת `DailyStatus` בזמן החישוב, כך ששינוי ספים או יעד לא משנה ימים קודמים.
